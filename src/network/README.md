# MSGI One network additions

These screens extend the existing Vite prototype. No backend was connected:
password recovery, support delivery, and notifications must **not** be represented
as live services. The default `App` receives no adapters.

## Integration boundary

Pass an `AppServices` implementation to `<App services={services} />` from the
application entry point when real services exist. Interfaces are in `services.ts`.
Do not put service credentials, token validation, email delivery, or database
operations in the browser. Adapters must use a real authenticated backend and
honour `AbortSignal`.

- `auth.requestPasswordReset` must acknowledge only a request actually accepted
  by the authentication service. The UI uses a non-enumerating message. The
  provider should generate a short-lived, single-use link using the provided
  redirect URL with `#/reset-password?token=…`. Reset tokens are not stored.
- `auth.validateResetToken` must validate the token server-side. The browser never
  declares a token valid based on its shape. `resetPassword` must revalidate and
  consume it atomically and apply the backend password policy. The update
  confirmation is rendered only after `{ updated: true }`.
- `support.submit` accepts form fields and an optional `File`. An adapter should
  deliver multipart data to an endpoint that validates ownership, lengths, MIME
  type, size and actual file contents, rate-limits submissions, safely stores or
  delivers the request, and returns `{ saved: true, reference }`. References must
  be unique and generated by the service. No ticket numbers are invented locally.
- `notifications.list/markRead/dismiss` must scope records to the authenticated
  recipient on the server. Read and dismissal state only changes after a service
  acknowledgement. No demo notifications or local persistence are used. A missing
  service shows an explicit connection notice and an honest empty state.

Registration and login now use the membership-authentication integration boundary
documented in `../auth/README.md`. No provider is configured by default, and
browser-local flags do not grant access to the application.

## Navigation

- Existing login **Forgot password?** → recovery.
- Existing login **Contact alumni support** → MSGI Support (no account details
  prefilled while signed out).
- Profile → Settings → Help → Contact support → MSGI Support, prefilled from
  the current profile.
- Every existing header bell → Notifications. Back restores the underlying screen.
- Notification destinations are resolved against real screens and known content.
  Missing destinations show an error instead of opening an unrelated item.

Current prototype destination IDs:

- Profile: existing numeric alumni ID.
- Message: existing numeric conversation ID.
- Feed: `priya-first-year`, `karthik-network`, `anjali-memories`.
- Event: `leaders-table`, `career-storytelling`.
- Opportunity: `zoho-senior-engineer`, `freshworks-design-lead`.

Production adapters should map their content IDs to a production router rather
than these existing prototype records.

## Preservation and motion

New screen styles are scoped in `network.css`. Colours, typefaces, radii, headers,
logos and form controls come from the existing app. No theme gradients are
redefined. `ui/motion.css` adds finite opacity/translate/scale animations and small
press feedback; `ui/motion.ts` provides short dialog dismissals. Both the OS
reduced-motion preference and the existing in-app switch disable motion.

No dependency or development-server changes are needed.
